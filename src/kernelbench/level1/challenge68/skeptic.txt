CURRENT AUDIT NOTE (2026-09-03)

This challenge is groups=1.  The shared raw allocating entry owns output
geometry, optional zero bias, allocation, and launch behind one functional
postcondition.  There is no host group dispatch, slicing/stitching, or separate
extent-helper call.  Any contrary caveat below is historical and superseded.

skeptic.txt — KernelBench L1 #68
================================

PASS verdict caveats (reviewer should be aware):

1. **TF32 disabled** in the ModelNew Python file
   (`torch.backends.cuda.matmul.allow_tf32 = False`,
   `torch.backends.cudnn.allow_tf32 = False`) so cuDNN cannot use
   TensorFloat-32 reduced-precision matmul on Ampere+, which would
   otherwise blow the atol=rtol=1e-2 tolerance on these workloads.
   Without this, the reference convtranspose accumulator picks up
   ~1e-2 relative error from TF32, which is beyond the eval threshold.

2. **Host-side groups dispatch**: the verified GPU primitive only
   handles the groups=1 case.  For groups>1, the bridge slices X/W
   per group, calls the primitive G times, and stitches the outputs.
   The slicing/stitching layer is unverified C++.  Each per-group call
   goes through the self-allocating verified entry
   `convt*_general_alloc_f32`, and the output spatial dims come from the
   VERIFIED extracted helper `convt_out_dim` — there is no longer a
   hand-rolled C++ output-size formula or `torch::empty` for the
   verified slab.

3. **Inherited verification debt** (acknowledged tree-wide):
   - `setup`, `teardown`, `kpre_sendable`, `kpost_sendable` in the
     plain `kernel_desc` are discharged with `solve` (no `magic ()`,
     no admit) — matching the Conv*/ConvT* Naive precedent.
   - (FIXED 2026-06-04) The former `assume pure (result ==
     convT*_out_at ...)` at the end of the per-thread `kf` body is now
     fully PROVED via the `convT3d_partial_at` loop invariant +
     `convT3d_partial_at_step` step lemma and a tid-decode match
     (same discharge as Conv3D.Naive).  No `assume pure` remains in
     `Kuiper.Kernel.ConvT3D.Naive`.

4. **Numerical tolerance** is the standard KernelBench fp32 setting
   (`torch.allclose(..., atol=1e-2, rtol=1e-2)`).  Worst-case
   per-element diffs measured during the dev test for #61 were ~3e-6
   when ref/new shared weights via state_dict — the kernel is bitwise
   close to the cuDNN reference on identical inputs.

5. **PyTorch `output_padding` invariant** in the bridge is checked
   as `out_pad < max(stride, dilation)` (per-axis) — matching
   PyTorch's actual TORCH_CHECK semantics (the strict `< stride`
   form used in some earlier bridges is wrong when `dilation > stride`).

6. **Kuiper kernel side conditions** (`SZ.fits` chain) are checked
   for the per-group dimensions in the bridge; the grouped channel
   dimension (Cin/G, Cout/G) is what the primitive actually sees.
