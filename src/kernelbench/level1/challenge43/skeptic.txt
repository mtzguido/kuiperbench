SKEPTIC — KernelBench L1 #43 MaxPool3D
======================================

The public extracted entry [maxpool3d_raw_alloc_f32] owns the complete
three-axis computation.  It allocates both intermediates, runs the W/H/D
WindowReduce1D passes, changes axis views through proved zero-copy full-layout
recasts, frees the intermediates, and returns one final allocation.  The C++
entrypoint only validates the refinements and invokes that entry once.

Its postcondition is input-linked and exact at f32: three nested
[windowreduce_result reducer_fmax_f32] expressions describe the W, H, and D
folds in implementation order.  The two [l2_bcm_pages] views state how the
unchanged bytes are reinterpreted between axes, and the final layout is
physically row-major (B,C,D_out,H_out,W_out).  There is no existential output,
host permutation, host allocation, chunking loop, or host-side kernel
composition.

The bridge retains only ordinary trust at the ABI boundary: PyTorch tensor
metadata/data pointers, checked integer conversion, wrapping the returned
cudaMalloc pointer, and cudaFree in its deleter.  It requires contiguous CUDA
f32 input rather than silently copying it.

No challenge-local admit, assume, or magic is added.  As with the shared
WindowReduce1D implementation, floating-point [fmaxf] behavior is specified
directly; no associativity/commutativity axiom is needed.
