Skeptic review — KernelBench L1 #49 (max reduction over dim=1)
================================================================

Verified contract
-----------------

The (B,D,M) input is verified to be viewed as B*M rows of D elements.  The
packaged block-reduction primitive returns one f32 per row, and the challenge
postcondition requires that value to approximate the real-valued maximum of
the corresponding non-empty row.  The local bridge proves the equivalence
between the primitive's chest-based maximum and the sequence-based challenge
specification.

This is a strong, non-vacuous semantic specification.  It intentionally uses
Kuiper's [%~] relation, so it does not claim bit equality across different
floating-point reduction orders.  The approximation abstraction is part of
the accepted Kuiper model for this audit.

Trust and limitations
---------------------

- The challenge wrapper contains no [admit ()], [magic ()], or [assume pure].
- It relies on the released Kuiper package's block maximum primitive and
  approximation model.
- Rows are non-empty by type, and the thread count is clamped to the row
  length so every reduction bucket is non-empty.
- The CUDA/PyTorch bridge and KernelBench oracle remain outside the F* proof.
