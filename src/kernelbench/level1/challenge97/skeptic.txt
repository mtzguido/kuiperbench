L1 #97 — Scaled Dot-Product Attention — skeptic notes
=====================================================

What's verified
---------------
The public, self-allocating `Kuiper.KB.SDPA.sdpa_f32` entry accepts ordinary
contiguous row-major Q, K, and V tensors and proves the complete operation:

  eOut %~ real_sdpa rQ rK rV

where:

  real_sdpa Q K V = softmax((Q @ transpose_pages(K)) / sqrt(D)) @ V

Inside one Pulse ownership proof it:

  - proves that row-major K[BH,S,D] has the same byte serialization as the
    page-wise transpose under a batched-column-major [BH,D,S] view;
  - allocates the score and output buffers;
  - runs Q @ K^T, scaling, row softmax, and probabilities @ V;
  - frees the score scratch buffer and returns the owned output buffer.

The transpose and Array3/Array2/Array1 changes are ghost layout changes and
extract to no runtime data movement. The output claim is directly over the
real inputs; no real-valued intermediate existential mediates it.

Numerical scope
---------------
The scale is computed inside Kuiper as 1/sqrt(D). Its link to
FStar.Math.Sqrt.rsqrt uses the repository's temporary local compatibility
assumption pending the corresponding Kuiper floating-intrinsic theorem.
Softmax and the complete result use Kuiper's `%~` relation. Concrete numerical
error bounds and guarantees for exceptional NaN/Inf behavior are intentionally
out of scope.

Host boundary
-------------
The C++ entry point only validates dtype, rank, equal shape, device,
contiguity, and the verified size/launch bounds; installs the input's CUDA
device guard; calls `Kuiper_KB_SDPA_sdpa_f32` once; and wraps the returned
pointer with a `cudaFree` deleter. It performs no PyTorch transpose, view,
allocation, kernel composition, output copy, or fallback computation.

Build note
----------
Kuiper_KB_SDPA is extracted with +Klas because row softmax is bundled into the
orchestrator. Its second GEMM remains an extracted call to the verified
Kuiper_KB_BatchedGEMM module, which the bridge includes in the same translation
unit.

Verdict
-------
FULL within the repository's stated `%~` numerical scope: one clean public
specification covers the ordinary Q/K/V API and all device-side composition.
