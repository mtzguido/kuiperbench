KernelBench L1 #82 — Depthwise 2D Convolution (square input, square kernel)
============================================================================

Reference (from KernelBench/level1/82_conv_depthwise_2D_square_input_square_kernel.py):

    nn.Conv2d(in_channels=64, out_channels=64, kernel_size=3,
              stride=1, padding=0, groups=64, bias=False)

    input  : (B=16, 64, 512, 512)
    output : (16, 64, 510, 510)
        H_out = (512 + 2*0 - 3)/1 + 1 = 510 (same for W_out)

Reduction depth per output pixel: 3 * 3 = 9 muls/adds.
Total fmadds: 16 * 64 * 510 * 510 * 9 ≈ 2.4e9 (~2.4 GFLOPs).

This is the simplest of the four depthwise challenges (#82-#85): all
spatial parameters square, no dilation, no padding.  Use it as the
template for the depthwise kernel proof; #83-#85 will follow by
parameterisation (asymmetric K, asymmetric input, dilation).

Why deferred
------------

Depthwise 2D conv is a specialisation of standard 2D conv with the
input-channel inner loop dropped.  At the time of this triage there
is NO `Conv2D.Naive` kernel in tree (see
src/kernelbench/level1/challenge50/STATUS.txt — Phase 0 spec only).
The natural Phase 1 strategy is:

  1. Wait for `Kuiper.Kernel.Conv2D.Naive` to land (some other agent
     is expected to ship it for #50).
  2. Specialise it: drop the (ic) loop, index weight as
     `w[c, kh, kw]`, fold the per-channel computation into the
     per-thread body.  Each output thread computes one
     `dwconv2d_single` value.
  3. Setup/teardown: per-channel split — `x[b, c, :, :]` is shared
     by `K_h*K_w`-many output threads.  `forevery_factor'` plumbing
     analogous to `Kuiper.Kernel.RowScale.setup`.

Estimated Phase 1 LOC: ~600 (kernel + proofs) + ~150 (KB
orchestrator) + ~80 (bridge / Python / run.sh).
