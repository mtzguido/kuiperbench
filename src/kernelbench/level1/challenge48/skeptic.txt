SKEPTIC — KernelBench L1 #48 Mean reduction over dim=1
======================================================

Scope
-----
Kuiper.Spec.MeanReduceDim and Kuiper.KB.ReduceMean.

Spec faithfulness
-----------------
The verified entry point [reduce_mean_fw_f32] establishes
[meanreduce_post] from Kuiper.Spec.MeanReduceDim: every output cell
directly approximates the real sum of its input row divided by D.  No
floating reduction witness appears in the public postcondition, and
1/D is computed inside the verified entry point rather than passed by
the bridge.

The (B, D, M) input is viewed via the existing
[Kuiper.Tensor.Layout.BCMPages] layout with parameters
(b=B, hw=M, c=D); row r=b*M+j of that view is the length-D slice
x[b, :, j].  No new layout, no new primitive — the kernel is the
composition of the verified [reduce_sum_fw_f32] (challenge 47) with
[Kuiper.KB.ScalarMul.smul_fw_f32].

Inherited debt
--------------
None new.  Inherits the [magic ()] [kpre_sendable] / [kpost_sendable]
fields of the underlying [reduce_batched_block] and [smul_fw_f32]
primitives — the same legacy debt every plain [kernel_desc] kernel in
tree carries.  ReduceMean itself adds zero new
[magic ()] / [admit ()] / [assume pure].

Edge cases
----------
- All-zero / all-equal input row: sum is exact, output is the exact
  PyTorch value.
- Non-finite behavior is governed by the project-wide approximation
  relation; there is no unconstrained result witness.
- D = 0: ruled out at the type level (szp).
- Large shapes: bounded by B*M ≤ max_blocks (2²¹), while the block
  reducer uses 1024 strided threads and permits D > 1024.  The KB
  harness shape (128, 4096, 4095) therefore lies inside the verified
  envelope: B*M ≈ 524k and D = 4096.

Performance
-----------
2 GPU launches: one block-per-row tree reduction over D cells, then
one element-wise scalar multiply over B*M cells.  Single launch
amortises the reduction across all B*M rows.

Follow-up
---------
- Generalise to 4D / arbitrary leading-dim layouts.
