STATUS — KernelBench L1 #44 AvgPool1D
=====================================

Phase 0 (functional spec) landed.  GPU kernel impl deferred.

Landed (verified, ADMIT=0):

  - src/lib/spec/Kuiper.Spec.Pool1D.{fst,fsti}
    Scalar-polymorphic functional spec for 1-D windowed pooling
    (max + avg, kernel/stride/padding/dilation).  The avg-pool
    spec uses the `%~` approximate-post pattern (mirroring
    `Kuiper.Spec.Frobenius` and `Kuiper.Spec.L2Norm`) because
    floating-point addition is non-associative — the
    existentially-bound FP partial sum approximates the
    real-valued window sum, and the output equals that sum
    multiplied by a caller-supplied `inv_k` of type `t`.

Per-challenge dimensions
------------------------

From `KernelBench/KernelBench/level1/44_Average_Pooling_1D.py`:

  batch_size = 64, in_channels = 128, input_length = 65536
  kernel_size = 8, stride = 1, padding = 4
  (no dilation parameter; spec instantiated with D = 1)

Output length per row (via `pool_out_len_1d` with D=1):

  L_out = floor((65536 + 8 - 1*7 - 1) / 1) + 1 = 65537

Output tensor shape (B, C, L_out) = (64, 128, 65537), flattened
to Array2 of shape (8192, 65537).

PyTorch quirks the spec handles
-------------------------------

`nn.AvgPool1d` defaults to `count_include_pad=True`, so padded
positions contribute 0 to the numerator and the divisor is
always K (= 8 here).  The spec encodes this in
`avg_window_sum_r` (out-of-bounds → 0.0R) and
`row_avg_pooled_1d` (output = `mul sm inv_k` for caller-supplied
`inv_k ≈ 1/K`).

Resume instructions
-------------------

See `src/kernelbench/level1/POOLING_DESIGN.md` for the full
design plan and recommended order of attack.

#44 is a good *second* target after the primitive is sanity-
checked on #45 (which has no overlap and no padding).  The
caller plumbing for #44 mirrors what `Kuiper.KB.LayerNorm`
does for `inv_n`: compute `inv_k` host-side as `div one
(count_of_int K)` and pass it as a kernel argument.
