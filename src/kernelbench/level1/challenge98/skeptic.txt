KernelBench L1 #98: KLDivLoss (reduction='batchmean')
======================================================

Spec: src/lib/spec/Kuiper.Spec.KLDivLoss.fsti

  res %~ real_kl N batch_size rp rt

where the f32 inputs approximate positive real sequences [rp]/[rt], and
real_kl uses the real operation t * (log t - log p) followed by the batch mean.

Faithfulness to PyTorch's
  F.kl_div(log(predictions), targets, reduction='batchmean'):
  * For each i: torch's kl_div formula reduces (when log_target=False)
    to  target * (log(target) - input)  where input = log(predictions).
    So target * (log(target) - log(predictions))  = our kl_step.
  * 'batchmean' divides by batch_size, not by N_total.  The verified entry
    computes this division itself.
  * [log_approx] and the arithmetic approximation laws connect every
    floating step to the direct real operation.

Inherited debt:
  * Float-summation associativity (same %~ pattern used elsewhere).
  * F32.log uses the platform libdevice logf; we trust it as a
    primitive (consistent with how F32.exp / F32.sqrt are treated
    elsewhere in Kuiper).

Edge cases:
  * The verified contract requires positive real inputs, matching the
    KernelBench generator's domain and the domain of real logarithm; the
    bridge now checks both tensors before entering the verified function.
  * Empty input forbidden by bridge TORCH_CHECK.
  * Falls back to torch reference for non-conforming shapes/dtypes.

The final result, including division by batch size, is inside the verified
boundary; the bridge performs no loss arithmetic.
