What landed (single verified entry — whole reduction is verified)
-----------------------------------------------------------------
- src/lib/spec/Kuiper.Spec.CrossEntropyLoss.fsti
    Direct real-valued functional spec [cross_entropy_post]: if the f32
    logits approximate the real sequence [rp], then

      res %~ mean_r (-log_softmax(crow rp C r)[targets[r]])

    with no existential floating-point intermediates.  [ce_term_r] is pinned to
    the verified [Kuiper.Kernel.LogSoftmax.log_softmax_real] (numerically
    stable subtract-max) path the kernel actually computes.  This equals
    the PyTorch per-sample CE  logsumexp(row) - row[target]  mathematically.

    (The previous Phase-0 stub — which mislabelled [rsum(exp(.))] as
    "logsumexp" and never subtracted the target logit, and was imported
    by nothing — has been replaced.)

- src/kernelbench/level1/challenge95/Kuiper.KB.CrossEntropyLoss.{fsti,fst}
    A SINGLE self-contained verified entry [ce_loss_fw_f32] that owns its
    scratch and performs the WHOLE computation inside the verification
    boundary:
      * per batch row b: copy the length-C row into scratch, run verified
        [log_softmax_gpu] in place, gather the negated target lane (the
        per-row CE loss) via the requires-established in-range target;
      * write all B per-row losses into a device buffer and reduce-sum
        them on-device with verified [HReduce.reduce];
      * compute and multiply by the verified reciprocal [1/B] internally.
    Post is exactly [Kuiper.Spec.CrossEntropyLoss.cross_entropy_post].
    Mirrors the verified L1 #99 TripletMarginLoss per-row-then-reduce
    pattern (carried-prefix loop invariant + final-lemma discharge).
    No admit / assume / assume pure / magic.  z3rlimit 40.

- src/kernelbench/level1/challenge95/kuiper_crossentropyloss_bridge.cu
    Single verified call: ce_loss_fw_f32(B, C, predictions, targets).  NO host
    reduction or bounds-check loop.  A tensor-wide predicate establishes that
    every target is in [0, C) before the call; it computes no loss arithmetic.

Notes / trust boundary
----------------------
- [Kuiper.Kernel.LogSoftmax.log_softmax_gpu], [Kuiper.Kernel.HReduce.reduce]
  are reused as verified black boxes (their contracts pin the in-place row
  to %~ log_softmax_real and the result to %~ rsum, respectively).  The
  HReduce block kernels carry the project-wide, disclosed kpre/kpost
  sendability debt (framework-level, not functional); no NEW assume/magic
  is introduced here.
- B per-row log_softmax launches (perf, not correctness); a batched
  LogSoftmax2D + indexed gather would be a future optimisation.
