## What is actually verified (the whole loss, as a function of all inputs)

The single verified entry `Kuiper.KB.CrossEntropyLoss.ce_loss_fw_f32`
carries an honest Pulse separation-logic contract whose post directly states:

    res %~ real_cross_entropy B C rp targets

where the input f32 logits are required to approximate [rp].  No
floating-point intermediate is existentially chosen.

with `ce_term_r C sp r t = - (log_softmax(crow sp C r))[t]`, pinned via
`%~` to the verified `Kuiper.Kernel.LogSoftmax.log_softmax_real` value
(the numerically-stable subtract-max log-softmax the kernel computes).
This is mathematically `logsumexp(row) - row[target]`, i.e. the PyTorch
per-sample cross entropy.

Crucially, BOTH the per-row terms AND the cross-batch reduction are now
inside the boundary:
  * the device-to-device row copy remains related to the corresponding real row;
  * each log-softmax loss approximates its real term;
  * the on-device reduction approximates the sum of those real terms;
  * the mean multiplies by an internally computed and proved `1/B`.
So the returned scalar is verified as a function of ALL B*C predictions
and ALL B targets — not of a single row.

Proof structure mirrors the verified L1 #99 TripletMarginLoss:
`ce_carried` carried-prefix loop invariant, `ce_inv_init` /
`ce_prefix_extend` extension lemmas, and a final sequence approximation.  Two
small standalone lemmas (`neg_approx_f32`, `ce_term_fold`) keep the
negation/`%~`-fold off the large loop context.  z3rlimit 40.

## What changed vs the previous review (the gap that is now CLOSED)

Previously this kernel verified only a PER-ROW primitive and the bridge
summed the B per-row scalars in an UNVERIFIED host `double` loop, then
divided by B.  That host reduction is GONE: the bridge now makes a single
verified call.  A tensor-wide predicate establishes that every target index
is in [0, C) before that call; it performs no loss arithmetic.

The old `Kuiper.Spec.CrossEntropyLoss` stub was dead (imported by
nothing) and mathematically wrong (`logsumexp_real` was defined as the
sum-of-exp with no `log`, and the target logit was never subtracted).
It has been replaced by a correct spec that the verified kernel `.fsti`
imports and whose `cross_entropy_post` is the kernel's actual post.
