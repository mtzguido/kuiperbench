Spec design points (consistent across the cluster):
  - n-D erased tensor (etensor3 / etensor4 / etensor5) with
    extensionality machinery (mirrors [chest2]).
  - read_padded{,1,3} : zero-padded boundary read at signed
    spatial indices.
  - unrank{,1,3}_*   : flat-to-nD index decomposition for the
    linearised reduction (mirrors unrank_ic in
    [Kuiper.Spec.Conv2D]).
  - __conv*_single   : recursive partial sum with zero-base
    + per-step lemma (mirrors __matmul_single in
    [Kuiper.Spec.GEMM]).
  - conv*_single     : bias addition.
  - conv*            : whole-tensor result via mkT4 / mkT5.
  - lemma_conv*_index : SMTPat hook that lets clients reduce
    [tacc (conv ...) idx] to [conv_single ... idx] automatically.

The accumulation is folded LEFT-to-RIGHT over a linearised index
(ic, k1, k2, ...) -- this fixes one specific summation order.
Floating-point implementations whose order differs need a
decomposition lemma analogous to [matmul_tiles_lemma] in
[Kuiper.Spec.GEMM].

Conv2DDilated additionally provides:
  - lemma_conv2dd_specialises_conv2d : at (Sh=Sw=s, Ph=Pw=p,
    Dh=Dw=1) [conv2dd] reduces to [conv2d].  Lets clients of
    the dilated kernel discharge the non-dilated case by a
    single rewrite.

Scalar polymorphism: all four spec modules are [scalar et]-
polymorphic.  An f32 implementation gets a real-arithmetic
approximate spec for free via the existing real_like / a_add /
a_mul / [Kuiper.EMatrix.lemma_to_real_matrix_approximates]
machinery, exactly as in [Kuiper.Spec.GEMM].

KB tolerance
------------

Conv accumulates many fp ops -> %~ approximate post over real
arithmetic.  fp32 ≈ 1e-4 tolerance per element.  The summation
order is fixed in the spec (left-to-right over the linearised
index); the kernel must use the same order or carry an
associativity-decomposition lemma.


What is NOT in any spec (deliberately)
--------------------------------------

  - groups > 1 (depthwise/grouped conv).  Not required for
    this cluster.  See [Kuiper.Spec.DepthwiseConv2D] in adjacent
    work for the depthwise case.
  - bias = None.  Modelled as bias = const_seq zero by caller.
  - Output-dimension computation.  Caller computes (h_out, w_out,
    d_out, l_out) and passes them in; avoids divisibility
    constraints in the type signature.
  - Mixed-precision accumulation.  All ops happen in [et].
