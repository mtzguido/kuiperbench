KernelBench L1 convolution cluster — current status
===================================================

The standard, transposed, depthwise, pointwise, and separable convolution
challenges are implemented end to end with verified Kuiper entry points.
Older per-challenge STATUS files retain historical implementation plans; this
file records the current verification boundary.

Public entry points
-------------------

* Conv1D (#67, #76): `Kuiper.KB.Conv1DAlloc`.
* Conv2D (#50, #55, #56, #62, #87): `Kuiper.KB.Conv2DAlloc`.
* Fixed Conv2D (#63, #80): challenge-specific allocating entries.
* Conv3D (#54, #59, #60, #66): `Kuiper.KB.Conv3DAlloc`.
* ConvTranspose1D (#64, #74, #79): `Kuiper.KB.ConvT1DGeneral`.
* ConvTranspose2D groups=1 (#57, #65, #69, #71, #78, #81):
  `Kuiper.KB.ConvT2DGeneral`.
* ConvTranspose3D groups=1 (#58, #61, #68, #70, #73, #77):
  `Kuiper.KB.ConvT3DGeneral`.
* The genuinely grouped ConvTranspose benchmarks (#72 and #75) use their
  challenge-specific verified grouped entries.
* Depthwise Conv2D (#82–#85): `Kuiper.KB.DepthwiseConv2D`.
* Separable Conv2D (#86): `Kuiper.KB.SeparableConv2D`.

For the parameterized families, the public raw entry computes the output
extent, constructs a zero bias when bias is absent, allocates the output,
calls the verified kernel, and returns the extent together with the device
pointer. Its postcondition is stated over the original inputs. The C++ bridge
performs ABI and verified-precondition checks, makes one Kuiper call, and wraps
the returned allocation. It does not divide to obtain output geometry,
allocate or initialize bias scratch, reshape or transpose tensors, or compose
multiple Kuiper calls.

The #86 entry performs both depthwise and pointwise stages inside one Pulse
function and has a postcondition for the complete separable convolution.

KernelBench #73 has a misleading `groups` test variable: `get_init_inputs`
passes it positionally into the model's `output_padding` parameter, and the
reference does not forward that parameter to `nn.ConvTranspose3d`. Its actual
operation therefore has groups=1 and output_padding=0; the Kuiper wrapper
matches that effective reference ABI.

Specification scope
-------------------

The functional specifications fix the source-order floating-point fold and
state `%~` correspondence to their real-valued operations. Concrete numeric
error bounds and behavior for NaN/Inf inputs are intentionally outside this
audit. No public real-level intermediate witnesses weaken the top-level result
relation.

Validation
----------

Final validation uses `make -j$(nproc) verify`, `extract-all`, the default
build, and `dist`, all without `ADMIT=1`. CUDA/KernelBench runtime tests also
require a CUDA-capable environment.
