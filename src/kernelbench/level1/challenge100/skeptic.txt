SKEPTIC — KernelBench L1 #100 Hinge Loss
========================================

Scope
-----
Kuiper.Spec.HingeLoss, Kuiper.KB.HingeLoss, and the challenge100 loader and
C++ bridge.

Verified top-level contract
---------------------------
The public entry [hinge_loss_broadcast_f32] consumes the canonical contiguous
GPU inputs directly:

  predictions : (B,N), row-major
  targets     : (N,)

It preserves both inputs and returns ownership of a fresh one-element GPU
buffer.  Its real-valued postcondition is exactly

  mean_{0 <= i < B, 0 <= j < N}
    max(0, 1 - predictions[i,j] * targets[j]).

Thus the target broadcast, pointwise hinge operation, reduction, and mean are
one verified composition.  There is no host-side [targets.repeat(B)] and no
Python fallback.

Implementation shape
--------------------
Kuiper allocates a private row-major (B,N) scratch buffer and copies
[predictions] into it, so neither public input is mutated.  A verified ghost
transpose reinterprets the same storage as column-major (N,B).  The package
[RowBroadcast] kernel then applies each [targets[j]] to logical row j; physical
cell (j,i) in that view is exactly row-major prediction cell (i,j).  No
broadcast tensor is materialized.

The resulting storage is viewed flat and passed to [HReduce.reduce].  Kuiper
performs the f32 division by B*N, allocates the one-element output, and writes
the mean to it.  The C++ bridge only checks the canonical contiguous ABI and
verified size bounds, makes one Kuiper call, and wraps the returned pointer
with a [cudaFree] deleter.

Approximation and edge conditions
---------------------------------
The proof relates every f32 multiply/subtract/fmax to
[real_hinge_step], carries that relation through the explicit broadcast and
sum, and relates the final f32 division to [real_hinge_broadcast].  B and N are
strictly positive.  The bridge also enforces the generated uint32 ABI,
[B*N <= max_blocks*max_threads], and [(B*N)+max_threads] fitting uint32 as
required by the reduction implementation.

Inherited debt
--------------
No new [admit], [assume], or [magic] is introduced.  The implementation uses
the existing verified Tensor allocation/copy/view APIs, RowBroadcast, HReduce,
and Map primitives from the pinned Kuiper package and KuiperBench library.
