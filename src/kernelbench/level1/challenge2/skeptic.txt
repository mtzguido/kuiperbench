Skeptic review — KB L1 challenge 2 (matmul wrapper)
========================================================

Verified component
------------------
Klas.GEMM.Naive3.g_matmul_f32_rrr:
the GEMM kernel is verified end-to-end in
src/klas/Klas.GEMM.Naive3.fst. Kahan-style summation in Naive3 keeps
the column-reduction error O(eps) regardless of K. No assume / admit /
magic is added by this challenge.

Unverified glue in the .cu bridge
---------------------------------
The bridge checks dtype/device/layout and Naive3's size bounds, allocates the
exact (M,N) result, and makes one Naive3 call. It performs no tile rounding,
padding, or output slicing; Naive3 has no tile-alignment precondition.

Result
------
run.sh PASSes against the KernelBench reference (correctness
check via kernelbench.eval.eval_kernel_against_ref).
No new verified Kuiper code was written; this is a thin
bridge over the existing Klas.GEMM.* primitives.
